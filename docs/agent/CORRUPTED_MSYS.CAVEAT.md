Symptom: `sh.exe`/`bash.exe` fail with `fatal error - add_item ... errno 1`, cascading into unrelated test failures (hooks abort, local-transport clones fail) that persist after the run because wedged `bash.exe` processes keep the corrupted shared section alive. Root cause (confirmed 2026-07-03): Windows Defender real-time scanning slows MSYS process startup until spawns pile up (~16 concurrent) and its hooks corrupt the Cygwin shared section. Fix: Defender exclusions for `C:\Program Files\Git`, the repo's `test\env`, and `sh.exe`/`bash.exe`/`git.exe` processes — this also made the suite ~3.7× faster (289s → 77s). If it happens on an unfixed machine recover with `Get-Process | Where-Object { $_.Path -like 'C:\Program Files\Git\*' } | Stop-Process -Force`. Treat mass test failures mentioning `add_item` as this issue, not code regressions.
